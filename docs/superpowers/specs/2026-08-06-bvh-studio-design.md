# BVH Studio — Mixamo형 모션 라이브러리 UI 설계

작성일: 2026-08-06
기반: `maxscript/bvh_biped_ui.ms` (원본 유지, 복사·확장)

## 1. 목적

`bvh-library`에 쌓인 개인 모션 클립을 Mixamo처럼 훑어보고 고르고 다듬어
바이패드에 입히는 3ds Max용 툴을 만든다.

기존 `bvh_biped_ui.ms`는 기능은 갖췄으나 UI가 MAXScript 롤아웃의 리스트박스와
스피너다. 클립이 늘어날수록 "어떤 모션인지 이름만 보고 알아야 하는" 문제가 커진다.
이 설계는 그 지점을 해결한다.

1. 클립을 **움직이는 썸네일 그리드**로 보여준다.
2. 속도·트림을 스피너 대신 **곡선과 핸들**로 조작한다.
3. 임포트·리타게팅 로직은 검증된 기존 경로를 그대로 쓴다.

## 2. 대상 환경

- 3ds Max 2024 — 내장 `pymxs`, `PySide2`, `shiboken2`
- 3ds Max 2026 — 내장 `pymxs`, `PySide6 6.5.3`, `shiboken6`, `qtmax 28.0.0`
- 두 버전 모두 설치 확인됨. 별도 Qt 설치는 필요 없다.
- **`qtmax` 는 2026 에만 있다.** 2024 의 site-packages 에는 `pymxs`, `PySide2`,
  `shiboken2` 셋뿐이다. 메인 윈도우 부모 지정에 `qtmax` 를 전제할 수 없다 (4절 참고).
- Qt 바인딩 차이는 `compat.py` 한 곳에서 흡수한다.
- 모션 라이브러리: `C:\work\Ai\bvh-library` (기본값, INI에 마지막 폴더 저장)
- 변환 헬퍼: `src/helpers/bvh.py` (기존)
- 클립 동기화: `src/helpers/github_sync.py` (기존)

## 3. 범위

### 포함

- 클립 썸네일 그리드 (움직이는 프리뷰, 호버 재생)
- 검색 + 파일명 기반 태그 필터
- 큰 프리뷰 패널 (재생, 방위각 전환)
- 타임라인 스크러버 + 드래그 트림 핸들
- 속도 곡선 편집 (비균일 타임워프)
- 팔 간격 곡선 편집 (시간에 따라 변하는 ArmSpace 오프셋)
- 바이패드 생성 + 임포트 (기존 로직)
- 미러, 배치 간격 (기존 로직)
- Motion Mixer 전송 (기존 로직)
- GitHub 클립 동기화 (기존 로직)

### 제외 (이번 범위 아님)

- 본별 회전 커브 편집 (탄젠트 핸들이 달린 진짜 그래프 에디터).
  바이패드는 쿼터니언 기반이라 오일러 왕복·짐벌·키 감소가 선행돼야 하며
  별도 프로젝트 규모다.
- 캐릭터 메시 프리뷰. 프리뷰는 골격만 그린다.
- CAT·커스텀 본 리그 지원. 이번엔 바이패드만.
- 클립 자동 태깅·분류 (모션 내용 분석)
- 원본 `bvh_biped_ui.ms` 의 폐기 또는 대체. 둘은 공존한다.

각 모듈은 350줄을 넘지 않는 것을 목표로 한다.

### 런처

`bvh_studio.ms`는 repo 루트를 `sys.path`에 넣고 `launch.py`를 호출하는 것이
전부다. 창 생성·상태 관리는 전부 파이썬 쪽에 있다.

### 메인 윈도우 부모 지정

`qtmax` 는 Max 2026 에만 있으므로 `compat.max_main_window()` 가 두 경로를 갖는다.

1. `import qtmax` 가 되면 `qtmax.GetQMaxMainWindow()` 를 쓴다. (2026)
2. 실패하면 `QApplication.instance().topLevelWidgets()` 를 훑어 Max 애플리케이션
   윈도우를 찾는다. (2024)

두 경로 모두 실패하면 부모 없이 창을 띄우고 상태줄에 경고를 남긴다. 부모가 없으면
Max 뒤로 숨을 수 있으나 기능은 동작한다. 창을 못 띄우는 것보다 낫다.

## 5. 데이터 흐름

```
bvh-library/*.bvh
  → parse_bvh()                     (기존)
  → skeleton.fk()                   조인트 월드 좌표
  → thumb.render()                  썸네일·프리뷰        [Max 개입 없음]
  → 사용자 조작: 트림 핸들, 속도 곡선, 팔 간격 곡선
  → prepare_for_biped(..., time_map=...)
  → <클립>_biped.bvh
  → maxbridge.import_clip()         biped.createNew + loadMocapFile
  → maxbridge.apply_arm_space()     ArmSpace 레이어 키
```

**브라우징 단계는 Max를 건드리지 않는다.** 클립을 넘겨보는 동안 씬이 오염되지
않고, 반응이 즉각적이며, Max가 떠 있지 않아도 라이브러리 모듈을 테스트할 수 있다.
Max가 개입하는 시점은 임포트 버튼을 누른 순간부터다.

## 6. 속도 곡선

### 기존 구현의 제약

현재 `retime(bvh, speed)` 는 프레임을 리샘플하지 않고 `frame_time` 만 나눈다.

```python
return BvhFile(root=bvh.root, frame_time=bvh.frame_time / speed, frames=bvh.frames)
```

균일 속도 변경에는 이 방식이 정확하고 무손실이다. 그러나 BVH는 파일당
`Frame Time` 을 하나만 가지므로 **구간별로 다른 속도는 이 방식으로 표현할 수 없다.**
비균일 타임워프는 프레임 재샘플링이 필요하다.

### 추가할 함수

```python
def warp(bvh: BvhFile, time_map: Sequence[float]) -> BvhFile:
    """time_map[i] = 출력 프레임 i가 가져올 원본 프레임 위치(소수 허용)."""
```

계약:

- `time_map` 은 단조증가해야 한다. 아니면 `ValueError`.
- 값은 `[0, len(frames) - 1]` 범위로 클램프한다.
- 반환 `frame_time` 은 원본과 같다. 길이만 달라진다.
- `time_map` 이 `[0, 1, 2, ...]` 인 항등 사상이면 원본과 동일한 결과를 낸다.

### 채널 보간

- **위치 채널** (`Xposition` 등) — 선형 보간.
- **회전 채널** (`Xrotation` 등) — BVH는 오일러 각도라 단순 선형 보간하면
  ±180° 경계에서 값이 튄다. 채널별로 **연속성 언랩**을 먼저 수행한다:
  인접 프레임 차이가 180°를 넘으면 360°를 더하거나 빼서 최단 경로로 만든 뒤
  보간한다. 언랩은 원본 프레임 시퀀스 전체에 대해 한 번 계산한다.

### UI → time_map

곡선 위젯은 제어점 목록 `[(원본위치, 출력위치), ...]` 을 만든다. 여기서
출력 프레임 수만큼 샘플링해 `time_map` 을 생성한다. 제어점 사이는 **선형 보간**을
쓴다. 제어점이 단조면 선형 보간 결과도 단조라서 단조성이 구조적으로 보장된다
(13절). 단조성은 테스트로도 확인한다.

### 기존 경로 보존

`prepare_for_biped` 에 선택 인자 `time_map=None` 을 추가한다.

- `time_map` 이 없으면 기존 `trim` → `retime` 경로 그대로 (원본 `.ms` 동작 불변)
- `time_map` 이 있으면 `trim` → `warp` 경로
- `speed` 파라미터는 유지한다. 곡선이 평평한 경우 UI는 `time_map` 대신
  `speed` 를 넘겨 무손실 경로를 탄다.

## 7. 팔 간격 곡선

바이패드 레이어 가중치 API는 검증되지 않았으므로 사용하지 않는다.
대신 기존 코드에서 이미 동작이 확인된 API만 쓴다.

현재 `applyArmSpace` 는 프레임 0에 키를 하나 찍는다
(`animate on` + `at time 0` + `biped.addNewKey`). 이를 곡선의 제어점 시각마다
키를 찍는 것으로 확장한다. 사용 API는 동일하고 호출 횟수만 늘어난다.

기존 동작 두 가지를 유지한다.

- 재적용 전 기존 `ArmSpace` 레이어를 삭제한다.
- 적용 후 `ArmSpace` 레이어를 현재 레이어로 남긴다. 바이패드는 현재 레이어까지
  합성하므로 0번으로 되돌리면 오프셋이 보이지 않는다.

## 8. 썸네일과 프리뷰

### 순운동학

`skeleton.fk(bvh, frame_index) -> dict[joint_name, (x, y, z)]`

채널 순서대로 회전 행렬을 누적해 조인트 월드 좌표를 구한다. 조인트 20개 남짓에
클립당 샘플 12프레임이므로 순수 파이썬으로 충분하다. numpy 의존을 만들지 않는다.

### 렌더

- 클립당 균등 간격 **12프레임**을 뽑아 그리드 셀에서 반복 재생한다.
- 골격은 선 하나가 아니라 **굵기가 있는 림 실루엣**으로 그린다. 관절은 원,
  뼈는 양 끝 굵기가 다른 사다리꼴. 막대 인간보다 실루엣이 읽힌다.
- 투영은 정직교 투영. 방위각만 바꿀 수 있게 한다 (정면 / 측면 / 3-4 뷰).
- 스케일은 클립별 바운딩 박스에 맞춰 정규화한다.

### 캐시

FK 결과와 정규화 정보는 `(getDir #userScripts)/bvh_studio_cache/<해시>.json` 에
저장한다. 파일 수정 시각이 캐시보다 새로우면 다시 계산한다. 두 번째 실행부터는
즉시 뜬다.

**라이브러리 폴더 안에는 아무것도 쓰지 않는다.** `bvh-library` 는
`github_sync.py` 가 GitHub 에서 받아오는 폴더라, 캐시를 그 안에 두면 동기화
대상을 오염시킨다. 캐시 키는 클립의 절대 경로 해시를 쓴다 (폴더를 바꿔도 충돌 없음).

### 목록 규칙

- `*_biped.bvh` 는 목록에서 제외한다 (기존 `listClips` 규칙 유지 — 변환 산출물이다).
- 태그는 파일명에서 추출한다. `artoke_spin-kick` → `artoke`, `spin-kick`.
  `attack-combo_00` → `attack-combo`. 숫자 접미사는 태그로 만들지 않는다.

## 9. 화면 구성

Mixamo 레이아웃에 대응시킨다.

| 영역 | 내용 |
|---|---|
| 상단 | 폴더 경로, 검색창, 태그 필터 칩, 새로고침, GitHub 동기화 |
| 좌측 | 클립 썸네일 그리드 (스크롤) |
| 우측 상단 | 큰 프리뷰 + 방위각 전환 |
| 우측 중단 | 이름, kimodo 변환 체크, 배치 간격, 미러, **바이패드 생성 + 임포트** (주 버튼) |
| 우측 하단 | 임포트 후 조절 — 바이패드 선택, 팔 간격 곡선, Motion Mixer 전송 |
| 하단 전체 | 타임라인 스크러버 + 트림 핸들 + 속도 곡선 |

주 액션은 화면당 하나다. 임포트 버튼이 시각적으로 가장 강하다.

## 10. 에러 처리

씬을 건드리기 전에 전량 검증한다.

- 트림 범위 역전, 단조증가하지 않는 곡선, 존재하지 않는 파일은 임포트 전에 차단
- `loadMocapFile` 실패 시 생성한 바이패드를 삭제한다 (기존 동작 유지)
- T포즈가 아닌 골격은 경고를 띄우되 임포트는 막지 않는다
  (`has_upright_spine`, 기존 동작 유지)
- 파싱에 실패한 클립은 그리드에 회색 카드와 사유를 표시한다.
  클립 하나가 목록 전체를 죽이지 않는다.
- 상태 메시지는 창 하단 한 줄에 모은다. 모달 대화상자를 쓰지 않는다.

## 11. 테스트

### pytest (Max 불필요)

- `warp` — 항등 time_map이 원본과 동일한 결과, 출력 프레임 수, 단조성 위반 시 `ValueError`
- 오일러 언랩 — 179° 에서 -179° 로 넘어가는 구간이 2° 이동으로 보간되는지
- `time_map` 생성 — 임의 제어점에서 항상 단조증가하는지
- `fk` — 알려진 단순 골격(2~3 조인트)의 좌표가 손계산과 일치하는지
- 라이브러리 스캔 — `_biped` 제외, 태그 추출, 캐시 무효화
- `prepare_for_biped` 회귀 — `time_map` 없이 호출하면 기존과 바이트 단위로 동일한 출력

### Max 내 확인

`3dsmax-mcp` 로 Max를 띄워 직접 검증한다.

- 창이 Max 메인 윈도우에 정상적으로 붙는지 (2024/2026 각각)
- 클립 임포트 후 프레임 수와 재생 길이가 프리뷰와 일치하는지
- 팔 간격 곡선이 시간에 따라 실제로 변하는지
- Motion Mixer 전송이 기존과 동일하게 동작하는지

## 12. 성공 기준

`bvh-library` 를 연 상태에서, 클립 이름을 모르는 사람이 썸네일만 보고 원하는
모션을 찾아 선택하고, 속도 곡선으로 구간별 완급을 주고, 트림 핸들로 앞뒤를
자른 뒤, 버튼 하나로 바이패드에 올릴 수 있다. 그 과정에서 원본
`bvh_biped_ui.ms` 의 동작은 전혀 달라지지 않는다.

## 13. 확정된 세부 결정

설계 검토 중 실물을 확인해 확정한 항목이다.

- **`qtmax` 의존 금지.** Max 2024 site-packages 에 `qtmax` 가 없음을 확인했다
  (`pymxs`, `PySide2`, `shiboken2` 뿐). 2026 에는 `qtmax 28.0.0` 이 있다.
  부모 윈도우 탐색은 4절의 2단 폴백을 쓴다.
- **제어점 사이 보간은 선형으로 확정.** 단조성이 구조적으로 보장되고
  (제어점이 단조면 선형 보간도 단조), 검증이 단순하다. 단조 3차는 쓰지 않는다.
  곡선이 각져 보이는 문제는 제어점을 늘려 해결한다.
