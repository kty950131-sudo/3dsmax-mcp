# BVH Studio 2D 트래킹 초벌 편집기 설계

## 목적

RTMW3D 영상 추론이 끝난 뒤 사용자가 영상 위에서 잘못 잡힌 관절을 직접 고치고, 보정 결과로 BVH를 다시 만들 수 있게 한다. DeepMotion 전체 기능을 복제하지 않고 **2D 관절 초벌 보정**에 집중한다.

## 확정된 작업 흐름

1. `영상 추가`로 RTMW3D 추론을 실행한다.
2. 완료되면 기존 라이브러리 화면 대신 트래킹 편집기를 연다.
3. 왼쪽 뷰포트는 원본 영상 프레임과 2D 관절 오버레이를 표시한다.
4. 사용자는 관절점을 드래그하고, 이전 프레임 복사·다음 프레임 전파·초기화를 수행한다.
5. 오른쪽 뷰포트는 해당 프레임의 3D 관절 결과를 비교용으로 표시한다.
6. `BVH 다시 생성`을 누르면 원본을 보존한 보정 JSON과 새 BVH·trace를 만든다.

## 화면 설계

- Figma 정본: `https://www.figma.com/design/BkbSvV39LzNNpfD4BvjGPO`
- 기본 배치: 2D 영상과 3D 관절의 좌우 분할, 하단 관절별 타임라인, 오른쪽 인스펙터.
- 색: 배경 `#08090B`, RTMW3D/정상 상태 `#48A9C5`, 선택·저신뢰 `#F5B642`.
- 글꼴: `Noto Sans KR`. 제목은 약한 음수 자간, 본문 행간은 글자 크기의 1.4–1.45배.
- 상호작용 모션: 선택 링 160ms 확장, 드래그 중 이전 위치 잔상, 전파 완료 시 타임라인 방향 표시. 모두 Ease Out, 160–240ms.
- Artoke 인체 SVG는 직립 기준체와 빈 상태 안내에만 사용한다. 실제 트래킹 관절 좌표를 대신하지 않는다.

## 데이터 모델

원본 `artoke.rtmw3d.v1` 파일은 수정하지 않는다. 현재 파일에는 BVH용 3D 좌표만 있으므로 추론기가 `image_size`와 프레임별 `image_keypoints`(원본 영상 픽셀 X/Y)를 함께 기록하도록 스키마를 확장한다. 기존 파일은 3D X/Y를 이전 방식으로 투영하는 읽기 전용 폴백만 제공한다. 편집 결과는 같은 구조를 유지하는 별도 파일 `<stem>_rtmw3d_edited.json`에 저장한다.

각 편집은 다음 최소 정보로 관리한다.

- 프레임 인덱스
- BODY23 관절 이름
- 수정된 원본 영상 픽셀 좌표 X/Y
- 원본 좌표와 원본 confidence
- 편집 상태: `manual`, `copied`, `propagated`

보정 JSON에는 `edited_from`, `edited_at`, `edit_count`를 추가한다. BVH 변환기는 기존 `load_rtmw3d()`·`convert_rtmw3d_file()` 경로를 그대로 재사용한다.

2D 수정으로 BVH를 다시 만들 때는 해당 관절의 깊이 Z를 보존하고, 같은 추론 프레임에서 얻은 X/Y만 수정 픽셀 좌표로 교체한다. 화면 CSS 좌표를 직접 저장하지 않는다.

## 구성 요소

### Python

- `scripts/run-rtmw3d.py`: 영상 크기와 smoothing 이전의 2D 픽셀 관절점을 결과에 함께 기록.
- `tracking_editor.py`: RTMW3D JSON 로드, 프레임 조회, 수정 적용, 원자적 저장, BVH 재생성.
- `StudioBridge`: 편집 세션 열기, 프레임 읽기, 수정 저장, 전파, BVH 재생성 슬롯.
- 영상 디코딩은 OpenCV로 요청 프레임만 읽고 JPEG 데이터 URL로 돌려준다. 모든 영상을 메모리에 올리지 않는다.

### HTML/JavaScript

- 기존 `studio_draft.html` 안에 편집기 뷰를 추가한다.
- 2D 뷰포트는 `<canvas>` 한 장에 영상과 관절선을 함께 그린다.
- 3D 비교 뷰는 현재 `drawPose()`의 투영 로직을 재사용한다.
- 드래그 좌표는 캔버스 크기가 아니라 원본 영상 픽셀 좌표로 정규화해 저장한다.
- 편집 상태는 프레임·관절 키의 Map으로 보관하고 저장 성공 후에만 dirty 상태를 해제한다.

## 전파 규칙

MVP의 자동 전파는 AI 재추론이 아니다.

- 기본: 현재 수정값을 다음 한 프레임에 복사.
- 범위 전파: 사용자가 지정한 종료 프레임까지 원본 관절 이동량을 유지하면서 수정 오프셋을 선형 감쇠한다.
- 덮어쓰기 전에 이미 수동 수정된 프레임이 나오면 멈춘다.
- 자동 optical flow와 IK는 이번 범위에서 제외한다.

## 오류 처리

- 영상·JSON 경로가 없거나 프레임 수가 다르면 편집기를 열지 않고 원인을 표시한다.
- BODY23 이름, 프레임 수, 좌표 유한성 검증을 저장 전에 수행한다.
- 저장은 임시 파일 작성 후 교체해 중간 파일을 남기지 않는다.
- BVH 재생성 실패 시 편집 JSON은 보존하고 기존 BVH는 덮어쓰지 않는다.
- 닫기 전에 미저장 수정이 있으면 확인을 표시한다.

## 테스트와 성공 기준

- 단위: 좌표 정규화, 단일 수정, 복사, 감쇠 전파, 수동 수정 충돌, 원본 불변성.
- 통합: RTMW3D JSON → 수정 저장 → 새 BVH 생성 → 3ds Max Biped 호환 본 이름 검증.
- UI: 관절 선택·드래그·프레임 이동·저장·재열기 후 같은 좌표가 보이는지 확인.
- 성능: 1080p 영상에서 프레임 요청 후 250ms 이내 화면 갱신을 목표로 하며, 최근 프레임 12장을 LRU 캐시한다.
- 회귀: 기존 영상 추가, 라이브러리, BVH 임포트 기능이 그대로 동작해야 한다.

## 이번 구현에서 제외

- 다중 인물 추적
- 손가락·얼굴 관절 편집
- optical flow 자동 추적
- 발 고정 IK와 물리 보정
- 3D 깊이 직접 드래그
- 학습 모델 재훈련
